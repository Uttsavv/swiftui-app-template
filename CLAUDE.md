# Project rules for Claude

iOS 26+ SwiftUI app, Swift 6 language mode, built with the latest Xcode. Project file is generated by XcodeGen from `project.yml`; never edit or commit `*.xcodeproj`.

## First session in a new app
If `docs/design-brief.md` says `status: draft`, before building any UI ask the user, in one message:
1. Colour scheme: mood, brand or accent colour, extra themes beyond system light/dark, colours to avoid.
2. Motion: personality (calm, snappy, playful), moments that deserve motion, haptics, anything that must never move.
3. Typography: system design (`default`, `serif`, `rounded`) or a custom font.

Then record the answers in `docs/design-brief.md`, set `status: confirmed`, and update `Theme.app` (palette in `Palette.swift` style, motion in `Motion.swift` style). Run the DesignSystem tests so every colour pair passes contrast.

## Design system (`Packages/DesignSystem`)
- Use tokens only: `theme.colors.*`, `.dsFont(_)`, `Spacing`, `Radius`, `.dsAnimation(_:value:)`, `.dsTransition(_)`. No hex values or magic numbers in feature code.
- Glass only on small floating controls: tab bar, toolbars, mini-player/status strips, floating buttons. Never on content, and never on sheets: give every sheet a solid background with `.dsSolidSheet()`. Prefer system bars, `TabView`, `.buttonStyle(.glass/.glassProminent)`. Custom glass: `dsGlass` inside `DSGlassCluster`. Don't put custom backgrounds on navigation bars, toolbars or tab bars.
- Corners: top-level containers use `Radius` + `dsContainer`; anything nested uses `dsConcentricBackground` / `dsConcentricClip`.
- No one-sided borders or accent stripes. Separate with fill, spacing, or an even hairline.
- Follow the system appearance; no in-app light/dark switch.

## Accessibility (required for every screen)
- Hit targets 44×44 pt (`dsHitTarget`). Every icon-only control has a text label.
- Dynamic Type up to accessibility sizes without truncation (`DSAdaptiveStack`). Text styles only, no fixed font sizes, no Light/Thin weights.
- Contrast: 4.5:1 text, 7:1 preferred for small text on custom colours, 3:1 large text and icons; light, dark and Increase Contrast. Add new pairings to `Palette.contrastRequirements`.
- Never rely on colour alone (`DSStatusLabel` pairs icon + text).
- Reduce Motion: use `dsAnimation`/`dsTransition`, which swap movement for fades. No autoplaying or looping motion without a control.
- Add each new top-level screen to `AccessibilityAuditTests`.

## Swift and SwiftUI
- Main-actor by default. Mark CPU-heavy or I/O work `@concurrent`. No `DispatchQueue`, no `Task.detached` unless justified.
- `@Observable` models, `@State`/`@Environment`/`@Bindable`; never `ObservableObject`.
- `NavigationStack`/`NavigationSplitView`, `Tab` API, `Tab(role: .search)`.
- Swift Testing for unit tests; XCTest only for UI tests.
- Strings go through the String Catalog. Use SF Symbols for icons.
- Performance: keep `body` cheap; no work in `init`, `body`, `onAppear` or gesture `onChanged`; cache results computed elsewhere. Build child content in `init` instead of storing `@escaping` view-builder closures. Avoid `GeometryReader` where a layout or `onGeometryChange` with a threshold works. Profile with Instruments' SwiftUI template when something hitches.

## Skills
`.claude/skills/` holds swiftui-pro, swiftdata-pro, swift-concurrency-pro, swiftui-liquid-glass and background-execution. Use them when writing or reviewing code in those areas.

## Commands
- `scripts/new-app.sh Name com.prefix` once, when starting a new app from the template.
- `scripts/bootstrap.sh` generates the Xcode project.
- `swift test --package-path Packages/DesignSystem` runs design-system tests.
- `xcodebuild test -scheme AppTemplate -destination 'platform=iOS Simulator,name=iPhone 17'` runs app and UI tests.
